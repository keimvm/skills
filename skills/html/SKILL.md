# HTML による説明資料

読み手が内容を理解するための資料を作る。文章の流れを整え、見出し・比較・図表を必要に応じて使う。

## 説明の組み立て

- 読み手が理解したいことを軸に、前提と要点、本論、具体例、補足をつなぐ。内容に合わない章を機械的に足さない。
- 一つの段落では一つの話を扱い、難しい用語は初出で短く説明する。用語欄だけに定義を任せない。
- 図は、難しい解説や関係・構造など、視覚化した方が伝わる箇所に置く。全体像の図も有効な場合に使い、冒頭の図解を必須にしない。
- 主要な説明はそのまま読める状態にする。補足や細かな説明は `details.mb-details` と `summary` で折りたたみ、初期状態は閉じる。
- 見出しを読めば話の流れが分かるようにする。長い資料にはリード文の後に `.mb-toc` の目次を置き、各節の `id` と対応させる。
- 事実・解釈・仮定を混同せず、参照した情報には出典リンクを添える。

## デザイン

作成前に [部品見本](design-system/component-samples.html) を確認する。配色・字体・部品は [document.css](design-system/document.css)、開閉と印刷時の動作は [document.js](design-system/document.js) を正とする。

- 背景は生成り `#FAF9F6`。部品は白地、黒罫線、角丸を基本とする。
- リンクは青 `#2990DA`、強いアクセントは赤 `#D63A2F`。赤い強調は原則1ページ1箇所まで。コードや差分の意味を示す色は別扱いとする。
- 本文は Ubuntu Sans と Noto Sans JP、コード・URL・日付は Ubuntu Mono を優先する。端末にない場合は同梱CSSのシステムフォントへ代替し、表示のために外部フォントを必須にしない。
- 元の文字サイズと余白を基本に、本文を読みやすく保つ。装飾目的だけでカードやチップを増やさない。
- 表は短い対応や比較に使い、3列までを基本とする。行見出しには `.mb-rowlabel` を付け、横に長い表は `.mb-table-scroll` で囲む。
- 引用には `.mb-quote` を使う。原文と訳文は同じ文字サイズ・色で上下に並べ、出典を明記する。
- `.mb-chip` は並列の固有名や分類名に使う。絵文字や矢印文字を図記号にせず、必要な記号はSVGで描く。
- 文書固有のCSSは、図の配置など必要な調整にとどめる。

## 用語欄

- 繰り返し参照する用語があるときに設ける。広い画面では本文右側、1399px以下では本文末尾へ置く。
- **初期表示は開いた状態**。画面上部の「用語欄を閉じる」で隠し、「用語欄を開く」で戻せるようにする。
- 閉じたときは用語欄の列と余白をなくし、本文が幅を使えるようにする。空の列や細いサイドバーを残さない。
- `.mb-wrap` 直下に `main.mb-main` と `aside.mb-glossary` を置く。見出し・リード・目次も `main` に含める。
- `.mb-glossary-toggle` の `aria-controls` と用語欄の `id` を一致させ、`aria-expanded` を開閉状態と同期する。同梱JSがこの操作を担当する。
- 用語欄が不要なら、欄と開閉ボタンを両方省く。JavaScriptが使えなくても本文と用語欄は読める構造にする。

## 図・コード・数式

- 図は `.mb-figure` にまとめ、表示面に `.mb-figure-frame`、説明に `figcaption` を使う。図の意味を本文でも説明する。
- 自作図は黒い線画を基本としたインラインSVGにし、代替説明を付ける。単純な直列手順には番号付きの説明を使う。
- 原典の図を使う場合は出典を付け、利用条件を守る。埋め込み画像には `alt` を付け、横幅を画面に収める。
- コードには言語クラスを付ける。色分けが必要なら生成時にハイライト済みHTMLを作り、同梱CSSの `.hljs-*` を使う。実行時のCDN読み込みを前提にしない。
- 差分は理由を文章で説明してから `pre.mb-diff` で示す。色だけに頼らず、追加・削除の行頭記号も残す。
- 数式は必要な場合だけ使う。MathMLや事前描画したインラインSVGなど、単一ファイルで表示できる形にし、LaTeX原文は選択・コピーできる補足に残す。未知の記法を勝手に別の式へ置き換えない。

## 単一HTMLの出力

- 成果物は、ブラウザで直接開ける **1つのHTMLファイル** にする。表示・開閉に必要なCSSとJavaScriptを本文へ埋め込み、外部ファイルやネット接続を必須にしない。
- 画像は必要に応じてデータURI、図はインラインSVGにする。別添アセットやCDNのCSS・JavaScript・フォントへの参照を残さない。通常の出典リンクは残してよい。
- [部品見本の原稿](design-system/component-samples.template.html) の骨格を使う。`<!-- html-skill:styles -->` と `<!-- html-skill:script -->` を各1箇所残し、以下で同梱CSS・JSを埋め込める。原稿本文は作成する内容へ置き換える。

```bash
python3 <skill-dir>/scripts/build-html.py <draft.html> <output.html>
```

- `<skill-dir>` はこのスキルの配置先に置き換える。Pythonを使わず直接埋め込む場合も、CSS先頭のMITライセンス通知を含める。
- 保存先はユーザー指定に従い、指定がなければ現在の作業ディレクトリに保存する。ファイル名は `{yyyymmdd}-{内容を表すケバブケース}.html` とし、既存資料の更新では名前を変えない。
- 原稿や見本の制作用ラベルを、説明資料の本文へ持ち込まない。最終回答には完成HTMLへのリンクを示す。
